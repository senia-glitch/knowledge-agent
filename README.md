# Помощник по базе знаний

Локальный MVP на готовом AnythingLLM. Один Docker-контейнер содержит веб-интерфейс, обработку документов, многоязычную embedding-модель и LanceDB. Ответы генерирует внешний провайдер. Собственных LLM, Ollama и сборки образов нет.

Развитие до устанавливаемого продукта ведётся по [плану](PLAN.md). [Архитектура оболочки](docs/ARCHITECTURE.md) зафиксирована на этапе 1; сама оболочка пока не реализована.

Перед каждым push: `python scripts/check-secrets.py --history`. Проверка не выводит значения ключей и блокирует обнаруженные локальные секреты и runtime-файлы в Git. Каталоги storage, backups и .secrets публиковать нельзя. В текущем репозитории подключён pre-push hook; после нового клонирования включить его можно командой `git config core.hooksPath .githooks` (нужен Python).

## Запуск на этом компьютере

1. Запустить Docker Desktop и дождаться готовности движка Linux containers.
2. В PowerShell из корня проекта выполнить:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

Скрипт создаёт локальные каталоги и копирует `.env.example` в `.env`, если настройки запуска ещё не созданы. Docker использует зафиксированный digest официального образа AnythingLLM 1.20.0 и скачивает его, если образ отсутствует. Повторный запуск использует ту же версию, данные не удаляет. Открывается страница с пошаговой настройкой:

- [Начало работы](http://127.0.0.1:3001/start.html)
- [AnythingLLM](http://127.0.0.1:3001/)

`ExecutionPolicy Bypass` действует только для этого процесса, глобальная политика не меняется.

## Настройка модели в браузере

На странице начала работы есть ссылки, описание шагов и кнопки копирования. Используется штатная форма AnythingLLM; страница подсказок сама не сохраняет ключи и не проверяет LLM.

1. В Settings → LLM Preference выбрать **OpenAI (Generic)**.
2. Для OpenCode Go задать Base URL `https://opencode.ai/inference/go/openai/v1`.
3. Вставить API-ключ из OpenCode Console в поле ключа. Не отправлять его в чат или Git.
4. Выбрать текстовую модель из списка Go. При ручном вводе нужен её точный ID; публичный список доступен по `/models` у указанного Base URL.
5. Начальный контекст 8192, максимальная длина ответа 1024. При необходимости скорректировать по возможностям модели.
6. Сохранить. Если форма не предлагает отдельной проверки подключения, отправить короткое сообщение в созданном рабочем пространстве, затем проверить ответ по документу.

Провайдер заменяемый: можно сменить Base URL, ключ, модель или встроенный профиль в настройках. Для провайдера с несовместимым протоколом нужен соответствующий встроенный профиль, произвольная CLI-подписка автоматически не поддерживается.

Используется официальный Go API без подмены клиента. В документации Go описаны требования к сторонним клиентам и области применения; технический успешный ответ не гарантирует решение провайдера о допустимости использования. При отказе или лимите приложение должно показать ошибку; обходы и платное превышение лимитов автоматически не включаются.

OpenCode требует заголовок сессии. Скрипт запуска добавляет постоянный `x-opencode-session` через штатный `GENERIC_OPEN_AI_CUSTOM_HEADERS`, не меняя код образа и ключ. В этой версии он общий для основного демонстрационного диалога. До работы с несколькими независимыми диалогами/пользователями потребуется раздельная передача сессий; эта возможность в текущем MVP не реализована.

## База знаний

`knowledge/` — исходные документы. Их появление в этой папке **не запускает автоматическую индексацию**.

В браузере:

1. Создать рабочее пространство «Моя база».
2. Загрузить `knowledge/demo-school.txt` в управление документами.
3. Добавить документ в рабочее пространство и выполнить **Save and Embed**.
4. В настройках рабочего пространства выбрать **Query**, температуру `0.1`, для первоначальной проверки порог поиска **No restriction**.
5. Вставить в System Prompt инструкцию со страницы начала работы.
6. Задать «Сколько длится занятие?» и проверить ответ 45 минут и источник.

Индексация: **Native / AnythingLLM Embedder**, модель **MintplexLabs/multilingual-e5-small**. Её размер по описанию разработчика около 487 МБ; загрузка выполняется при первой индексации и сохраняется в `storage/models`. Если выбран другой embedder, повторно проиндексировать документы.

TXT, Markdown, DOCX и PDF с текстом подходят для начала. Сканам требуется OCR. Для обновления файла удалить старую версию из рабочего пространства и добавить новую; проверять ответ в новом чате, чтобы старая история не влияла на проверку.

Полная [проверка приёмки](verification/acceptance.md) включает отсутствие ответа, перефразирование, обновление и перезапуск. RAG может ошибаться: ссылки и ответ нужно сопоставлять с источником.

Текущее состояние приложения и число проиндексированных документов:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\check.ps1
```

Этот скрипт не проверяет ответы модели. Фактические результаты первоначального запуска записаны в [verification/STATUS.md](verification/STATUS.md).

## Остановка и состояние

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\stop.ps1
```

Для журналов и состояния (из PowerShell):

```powershell
$env:DOCKER_CONTEXT = 'desktop-linux'
& 'C:\Program Files\Docker\Docker\resources\cli-plugins\docker-compose.exe' ps
& 'C:\Program Files\Docker\Docker\resources\cli-plugins\docker-compose.exe' logs --tail 80 anythingllm
```

На Linux-сервере используется обычный `docker compose`, путь к Windows-плагину не нужен.

## Данные и резервное копирование

- `storage/` — база приложения, индекс, документы и модели. Файл `storage/.env` может содержать ключ провайдера; каталог исключён из Git.
- `.env` — зафиксированный образ и порт. Пример `.env.example` не содержит ключей.
- `backups/` — место для локальных копий. Для согласованной копии остановить только этот проект, скопировать `storage` и `.env` в новый каталог резервной копии, затем запустить проект. Копия содержит секреты и не должна публиковаться.
- Docker хранит слои образа в своём существующем хранилище. Оно не переносится этим проектом; служебные файлы Docker могут оставаться на C.

Порт публикуется только на `127.0.0.1`; соседние контейнеры не останавливаются. Контейнер не получает Docker socket, privileged-режим, SYS_ADMIN или доступ ко всему диску. Браузерные инструменты агента в MVP не используются. Лимиты контейнера: 4 ГБ RAM и 2 CPU.

## Что пока не входит

Автоматическое чтение папки, генерация презентаций, интеграция с будущим продуктом и публичное размещение. Перед размещением на сервере нужны отдельная настройка входа, HTTPS и проверка резервного восстановления.
