# Knowledge Agent — план развития

Репозиторий: https://github.com/senia-glitch/knowledge-agent

## Цель

Устанавливаемый продукт с веб-панелью в личном стиле пользователя. После установки пользователь подключает внешнюю модель, добавляет документы и получает ответы по базе с источниками. Можно открыть полный интерфейс AnythingLLM. Предусмотрена установка на Windows и Linux-сервер.

AnythingLLM сохраняем как готовый движок чата, обработки документов и поиска. Не переписываем его функции. Оболочка использует fastbase и core-package. event-infra/PostgreSQL добавляются при появлении собственной задачи хранения: отдельная БД оболочки сейчас не требуется. Дизайн — my-design-system, тёмная и светлая темы.

## Исходное состояние

- Работает готовый контейнер AnythingLLM 1.20.0 с закреплённым digest.
- Многоязычная индексация внутри того же контейнера; данные сохраняются в storage.
- Go подключён через Generic OpenAI; ответы по базе и отсутствие выдуманных сведений проверены.
- Проверены обновление документа и сохранность индекса после перезапуска.
- Есть ограничение: один постоянный заголовок Go для демонстрационной сессии. Раздельные сессии должны появиться до заявления поддержки нескольких диалогов.
- Свои данные и ключ пользователя остаются локальными и не включаются в Git.

## Порядок работы

Этапы реализуются отдельно, по одному за подход. После каждого законченного этапа: соответствующая проверка → обновление статуса в этом плане → локальный коммит → проверка `python scripts/check-secrets.py --history` → push в main указанного репозитория → короткий отчёт. Одна небольшая задача может занять больше одного коммита, если обнаружится самостоятельное изменение.

Не отправлять в Git ключи, storage, резервные копии, локальные журналы и кэши. Не делать force push. При блокировке публикации сохранить локальную работу и назвать причину.

## Что означает «готово»

Готовность продукта означает проверенный пользовательский путь, а не наличие файлов или запущенного контейнера. Установка готовых образов с GitHub проверяется после фактической публикации образа и доступности пакета. До этого проверку локальной сборки не называть проверкой релизной установки.

Публикация исходников и образа на GitHub разрешена поэтапным push и workflow. Развёртывание на реальном сервере выполняется отдельно, когда известны сервер и домен; без них готовится и проверяется конфигурация, но не заявляется фактическое размещение.

Генерация презентаций/постов и автоматическое наблюдение за папкой — дальнейшее развитие после готовности этого продукта.
